# AG News v6 routing and matched continuation protocol

**Status: fixed development specification.** Each executable/source/config lock records its actual freeze time. B continuation has started under its earlier lock; A source and controls are now frozen before A model scoring. This is not external preregistration. This is a bounded selector and supervised-continuation study, not a Sleep or HOPE reproduction. It uses only the already-used AG News train/validation roles; every result remains exploratory. The reserved within-train set stays unopened.

## A. Fixed-context routing controls

For each of seeds 17, 29, and 43, compare the exact qualified warm adapter context with that seed's sealed `warm_CMS_reference` step-448 adapter context. The frozen 3B backbone is shared. These are two alternative complete mutable adapter states, not one model that retained knowledge through Sleep. All selectors use the same two contexts; constant selectors still retain both, even when one is unused.

The six primary selector conditions are constant-warm, constant-new, a train-supervised correct-phase ridge gate, a balanced-permuted-phase ridge gate, one fixed label-independent hash-random selector, and `uniform_intermediate_mix`, a fixed 0.5 blend of old/new final-MLP memory outputs with a 0.5 blend of the two readout-LoRA contributions. This is an intermediate hidden/logit construction, not a probability or weight average. Also report two predeclared format-conditioned, label-free confidence diagnostics: compare branches using either `log P(known common marker | prefix)` or `log P(known common marker | prefix) + max_full_vocab log P(second token | prefix, known marker)`. Ties select warm. These use the shared marker, never the gold class token. Report the validation task-ID diagnostic separately: it chooses warm/new using the known old/new validation partition and is never a deployment selector.

The correct gate maps the 1,024 training records' existing `phase` membership (`old`/`new`) to targets (-1/+1); this is task-phase supervision derived from class labels, not a wholly label-free router. The permuted control applies one fixed, balanced permutation to those phase targets before fitting the same ridge. Neither fit sees validation labels. Both use the frozen original-final-MLP feature at the last article-prefix position, training-only mean/std normalization, float64 dual ridge, fixed regularization 1, and threshold 0. The validation partition is used only for locked reporting. Since the original backbone, feature inputs, and training records are shared across seeds, first verify the feature hash is identical across seeds; fit each ridge exactly once and reuse it. A mismatch stops the run for review; do not fit per seed.

Hash-random uses one precommitted salt over a stable private row key, without class stratification or salt search. Freeze the two confidence equations, mixture coefficient, tie behavior, and hash salt before scoring. The confidence diagnostics use both branches' outputs. `uniform_intermediate_mix` evaluates both final-MLP memory branches and both readout-LoRA contributions. Report the shared-backbone call and each adapter-tail operation separately; do not equate its cost with a probability mixture or one selected tail.

Implement one shared frozen-backbone/original-final-MLP forward; obtain the gate feature from that same forward. For constant/correct/permuted/hash selectors, the current implementation evaluates both low-rank memory/readout branches and then selects each row's output, so it saves a duplicate 3B backbone pass but does not save the second adapter-tail computation. Before any model scoring, a CPU fixture must compare each shared-prefix branch's marker/class logits against its ordinary full-branch forward, including mixed branch assignments, route policy, and readout accumulation state. The uniform mix is defined operationally: blend the two memory outputs by 0.5, pass that result through the normal final normalization, then blend the old/new readout-LoRA contributions by 0.5 alongside the shared base head. Test this with a nontrivial final normalization; a toy without final normalization is insufficient. Do not claim one-backbone parity until this passes. Confidence and uniform-intermediate conditions also evaluate both branch tails. The task-ID diagnostic uses a known validation label and is diagnostic only.


Report full-vocabulary two-token EM, marker/class NLL, four-candidate accuracy, task-group confusion, and per-class denominators on the training and validation roles. The locked scorer teacher-forces the known common marker to obtain both positions in one model forward; strict EM still requires the model's first-token greedy prediction to equal that marker and its second-token greedy prediction to equal the class token. This is a fixed two-position scoring protocol, not arbitrary autoregressive generation: real generation would call the model once per generated token (the current path has no KV cache). Count one shared backbone forward per scoring call, and do not infer generation throughput or claim one call produces two unconstrained tokens. Training gate-fit metrics describe fit only; do not use them to tune the gate. The primary phase-A contrast is correct versus permuted train-group labels at the same two-context storage and the same fixed ridge; all other selectors are fixed diagnostics, with their extra inference cost shown separately.

Both saved adapter contexts total 54,793,600 logical bytes; exact equal-tensor deduplication leaves 28,576,459 bytes of unique adapter storage (27,396,800 bytes for one context plus 1,179,659 additional bytes across nine unequal tensors). The two float64 ridge parameter sets total 147,456 bytes. This is tensor-level accounting, not measured peak VRAM. A single 3B backbone is shared. Exact-equal tensor aliasing is allowed only after both contexts are loaded and verified, for read-only evaluation; never alias a tensor that continuation training can mutate. The v5 probe loaded the two states sequentially and ran two full forwards per article, so it did not measure a resident dual-context GPU implementation.

## B. Fixed-budget supervised continuation

For each seed, start from the exact `warm_CMS_reference` step-448 checkpoint, including controller state, execution policy, pending-window state, and RNG. Keep the qualified warm context frozen as the integrity/reference teacher. Continue the new context to **total primary step 1,024** (576 additional ticks), not 1,024 additional ticks. This endpoint is fixed for all seeds and arms; do not stop early, select seeds, relax gates, or resume a failed run. Bind the existing step-448 checkpoint as the starting reference; save new fixed checkpoints at total steps 512, 768, and 1,024, including model, controller, execution state, and RNG. Phase B is a continuation comparison on the updated CMS context; it does not apply the phase-A routing gate or combine the warm and new contexts during training.

Use two compute-matched arms: `new+new CE` and `new+old-gold CE`. Each primary tick has one B4 primary-new loss plus one independently scheduled balanced B4 auxiliary loss. The first arm's auxiliary batch is new data; the second arm's is old data with gold labels. Each loss has coefficient 1; accumulate both gradients, clip once at 1, and call CMS collect once with base/expert learning rates 0.02/0.04 and periods 4/16. The two arms thus match two student forward/backward batches and one controller tick, but differ in supervision and example exposure: 8 new-labelled examples/tick versus 4 new + 4 old. This is a compute-matched extra-training versus supervised-replay contrast, not equal-information training or Sleep.

Use the existing frozen 4,096-entry new schedule through total step 1,024, after verifying its hash and structure against the locked pack. Each entry is one B4 batch (four integer record indices); the continuation consumes the original entries indexed 448 through 1,023 without regenerating or reshuffling them. Generate and hash separate deterministic, class-balanced B4 auxiliary-new and auxiliary-old schedules before training; no validation or reserved rows may enter any schedule. Continue the exact controller/RNG state at step 448, where periods 4 and 16 are aligned. If any schedule or restore assertion fails, stop without retry or gate relaxation.

At total step 448, bind the already sealed v5 validation result as the inherited baseline. At 512/768/1,024, score each of the six arm/seed continuation contexts on the same 512-example validation set; score each arm's 1,024-example training set at the fixed terminal step. Report all six runs, even if a gate fails. No checkpoint selection, early stopping, threshold search, or held-out scoring. The warm context is retained only for teacher-integrity checks in this phase and is not included in these raw-continuation scores. Performance of the updated context under old gold CE is supervised replay, not autonomous consolidation.

The primary phase-B contrast is old-gold versus auxiliary-new at equal update, batch, and clip counts. It does not isolate information content: the arms receive different old/new label exposures. Report all fixed checkpoints without choosing the better endpoint. Only after the full phase-B seal, run a separate, source-locked phase-A inference pass over all six terminal contexts. Reuse the prefit phase-A gates and warm-context row cache; score every predeclared selector and confidence/task-ID diagnostic for every seed/arm, without selecting a case by metrics. This reports post-hoc context selection at step 1,024 only; steps 512/768 have raw continuation scores only. Freeze and review that inference runner before the training phase starts.

## Accounting and interpretation

Phase A retains one shared frozen backbone and two adapter contexts. Its unique adapter storage and gate-vector accounting are above; report logical checkpoint bytes separately from physical deduplicated tensor bytes. Report measured prefix forwards, adapter-tail evaluations, input-token proxy, CPU ridge fits, and wall time. A full-backbone forward count is not FLOPs or latency. The two branch checkpoints are stored on CPU and copied/restored as required; do not infer v5 peak VRAM from adapter byte counts.

Phase B adds 3 seeds × 2 arms × 576 = **3,456 primary ticks** and **6,912 B4 student forward/backward batches**. The old-gold arm consumes 6,912 old-row presentations; the new+new control consumes 6,912 auxiliary-new presentations, in addition to each arm's 6,912 primary-new presentations. Record actual padded-token proxy by stage. Any engineering qualification of at most 12 primary ticks/24 B4 forward-backward batches is costed separately and is not scored or included as scientific evidence. Each runner invocation has a cooperative 1,800-second limit: phase A counts from invocation, including static loading/preflight/planning, while phase B starts its active-work timer after preflight and plan creation and records setup time separately. The resume qualification has its own 600-second active-training cap after CPU preflight. Failure stops that phase; preserve completed receipts and do not retry or extend the cap.

The same AG News train/validation roles have already been used in earlier development, and AG News may have appeared in pretraining. Phase A fitting and Phase B continuation are adaptive development, not independent confirmation. Do not claim a Sleep retention benefit, general continual-learning result, or test-set improvement. Keep full failure and negative-result records.
