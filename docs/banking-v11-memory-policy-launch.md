# Banking V11 memory-policy launch path

`tools/launch_banking_memory_policy_v11.py` is a V11-only, single-run wrapper. It leaves the frozen V10 driver/runtime and the reviewed V10 launcher unchanged. Each invocation launches one `(seed, arm)` pair from the pre-registered V11 grid; it does not provide a preparation-only substitute for the six task-1 training/development runs.

The launcher reads a SHA-pinned contract, verifies the runner and reviewed V10 policy-helper source bytes, then invokes the V11 runner's real CPU preflight. That preflight checks the child configuration, V10 source/data binding, V10 main-grid seal, paired task-0 foundation receipt/checkpoint, and the run-specific output path. The frozen V11 preflight result uses a legacy `training_manifest_sha256` key for the train JSONL digest (`manifest.files.train.sha256`), while the launch contract's `training_manifest_sha256` is the SHA-256 of the complete train/dev pack-manifest file. The wrapper checks the pack-manifest file against the contract and the producer's train-file digest against the manifest's `files.train.sha256`, then records distinct normalized `training_manifest_sha256` and `training_file_sha256` fields. It also checks the other resulting digests, seed, arm, no-test assertion, and no-update/no-model assertions against the contract. Only after those checks does it set process-local `PYTORCH_CUDA_ALLOC_CONF=garbage_collection_threshold:0.7`, check the reviewed PyTorch build, and register `set_per_process_memory_fraction(0.8)` through `torch.cuda._lazy_call`. CUDA must still be uninitialized at registration.

The wrapper then runs the existing V11 `--phase run` command unchanged. It verifies the terminal receipt, paired V10 SLEEP task-1 checkpoint reference, task-1 update presence, immutable-model guard, test-isolation fields, and final checkpoint bytes. Its launch record preserves the source/config/seal/foundation digests and whether the queued memory callback ran. Every invocation is a new single-run contract; no six-run contract or child configuration is created here.

Contract schema: `banking-v11-memory-policy-launch-v1`. Required hashes are the actual V11 runner, this wrapper, the reviewed V10 policy helper, V11/V10 source locks, child config, train/dev manifest, V10 main seal, selected foundation checkpoint, completed V10 official-test JSON, and its evaluator source. Before installing the policy, the wrapper checks the official-test JSON's training config/source/manifest/seal bindings, all nine verified seed/arm contexts, pinned test-source revision/hash/row counts, and frozen/no-update indicators. The contract also pins the V10 and V11 config paths, source/project/model/data/seal/foundation/evaluation paths, seed, arm, device, fresh output directory, and separate fresh launch-record path. Do not create or execute this contract until the V10 main grid and official-test evaluation are complete and the V11 child configuration is actually frozen.

There is no model, batch, optimizer, numerical, or training-schedule modification in this wrapper. It only manages process-local memory policy and verifies the existing V11 run's bindings and terminal artifacts. No GPU run is performed by its CPU tests.
