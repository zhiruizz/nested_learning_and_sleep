# Banking77 v10 development protocol

Historical status at the numerical freeze (2026-11-07): all three task-0 foundations qualified and the transfer/recovery probe completed; the nine-run main grid was in progress and the official test payload had not been acquired. This document records the prospective design. Later outcomes and operational amendments are in the [V10 result report](../reports/banking77-controls-v10.md) and [V11 follow-up](../reports/banking77-reward-ablation-v11.md).

The goal is to distinguish receiver routing and teacher transfer failures from forgetting during new-task wake updates. This is a local last-MLP CMS experiment with a frozen Llama-3.2-3B base backbone, not an exact reproduction of native HOPE or the Sleep paper. CLINC v8 official test results were already exposed; they are historical results, not a fresh confirmation set for this experiment.

## Source and isolation

ModelScope candidates could not be established as exact mirrors of the original corpus. Their metadata query failures do not establish absence. The user was informed of the Banking77 Hugging Face fallback, fixed revision and size before acquisition. The acquired file is the original publisher's train CSV at commit `9d081458ff52e53cf7e848f414e6e9344e4e6696`, SHA256 `b06e26ac675513959a63135f11b94ea7786ed02da65db93a5650d8838cbc664b`, 839,073 bytes, 10,003 rows, 77 classes, CC BY 4.0. The official test file is withheld until the complete frozen run grid is sealed.

NFKC/casefold/whitespace-normalized text groups are formed before splitting. Conflicting-label groups are quarantined; four same-label duplicate rows were excluded. Within each class, a fixed hash rank with split seed 20261107 assigns 10 unique rows to development, then retains every other unique row for training. No model score enters row selection. Result: 9,229 training and 770 development rows, 25-177 training rows per class, no normalized-text overlap. The training pack SHA256 is `ed9f4b047768021cbf16a3fa042db12baf212038f89f33a00099f2e32b7300f3`.

An initial balanced minimum of 32 training rows plus 10 development rows failed on metadata, before pack creation or model evaluation: the smallest original class has 35 raw rows. The revised natural-count rule preserves data instead of excluding that class or repeating its examples. Both this failure and the revision are retained.

## Staged experiment

Seven tasks contain 11 classes each; independent fixed class orders use seeds 17, 29 and 43. Prompt framing, segmented tokenization without BOS, backbone, initialization, batch size and wake learning rates are shared by all arms. The primary decoder ranks all 77 canonical labels by total conditional log likelihood including EOS. It receives the full label dictionary but no task identity or candidate mask. Mean token score and free generation are secondary diagnostics; their inference cost and additional dictionary information are explicit.

Each seed first learns task 0 with CMS only for a fixed budget. All three foundations must meet predeclared global-77 accuracy >=0.50 and task-0 class macro accuracy >=0.40 on their 110 development rows before any main continuation. No seed replacement, threshold reduction or checkpoint selection based on a better development point is allowed. Failed qualification is a reportable outcome.

A separate, development-only transfer probe starts from qualified task-0 teachers, applies an identity prospective base update, resets the sender, and tests receiver transfer at fixed 3- and 30-update checkpoints. Additive expansion initially preserves the prior routing function; sender reset is a separate functional intervention. This probe must not be called a scheduled main boundary or an independent test confirmation. The foundation context and pending wake state are reconstructed and checked in the real 3B load. A separate exact disk-replay comparison covers the consolidation transaction context, routing policy, Adam, sample generator and process RNGs at opportunities 3-6. This is transaction-level recovery evidence; it is not a full-job interrupted/resumed training comparison. Main checkpoints are forensic snapshots, and the current driver has no production `--resume` CLI.

Planned main arms are CMS_ONLY, SLEEP_ADDITIVE and GOLD_ADDITIVE. Each starts from the same seed's exact foundation checkpoint and wake schedule. Sleep and gold arms share receiver allocation, sender reset, selected prompt identities and call opportunities. Gold replay uses extra known labels; equal counts are not equal information or FLOPs. Additive routing is our intervention, not a paper-prescribed policy. Only receiver A/B are trainable during consolidation; old parameters and teachers are guarded. Nonfinite gradients fail before a physical optimizer update; an exactly zero complete objective may instead be explicitly skipped and counted.

The intended two epochs per task and periods 16/64/256/1024/held-fixed count minibatches. They are local assumptions, not the paper's unexplained 512/2k/8k units. Pending base-gradient windows carry across tasks without forced flushing. Wake minibatches have size 8; global-candidate evaluation uses exact-length batches of at most 32 in every arm and phase. The tokenizer-only audit established a longest target of nine label tokens plus EOS, so all Banking rollout caps are ten, rather than the insufficient historical CLINC cap of eight. All 9,999 packed requests fit the reserved body budget without truncation. Segmented and joint token IDs differ for all requests, but decoded text matches exactly when optional decoder cleanup is disabled.

The frozen schedule/capacity audit and fixed wall/forward/update limits are recorded with the actual source pack. The completed finite probe retained the predeclared 30-opportunity budget; its 3/30 metrics were not used to select a best checkpoint, and no official test data entered this decision. A zero LTI reward does not eliminate its KL term: the complete local objective remains 0.5 KL + 0.5 reward CE. Only an exactly zero complete objective may be explicitly skipped without Adam, and this is separately counted. Gold and Sleep match call opportunities, not a guaranteed identical count of physical optimizer steps. No dummy gradient is added to force an update.

## Reporting

Record all seeds, negative/failing attempts, sample coverage, teacher validity, gradient norms, forward/token/update costs, parameter and checkpoint storage, and separate development exploration from the once-frozen official evaluation. Publish code, source/config locks and aggregate results only; no data, weights, secrets or checkpoints. Ubuntu's independent four-run All+N queue is observed read-only, and its checkpoints remain under `/mnt/dsm_workspace`.

The numerical config file is `configs/banking_v10_frozen_k10.json` (SHA256 `785ded5cc9d205dc3cbc6d25179abf6fd0d589ce6943a42626aa1692b54dfd9d`); its semantic hash is `f65c55587c3795b83d0d62695dbfc0501aa2927576e492d6185dd18e5558e7e4`. The 24-file computational source lock is `3fcc2e2cb930149e9ee5204dcf8fa8910888cd7b05cd31f66d10ceb852d6844c`. The actual main release binds all qualified foundations and the independently reviewed real probe, including exact disk replay.

Two operational failures are retained separately from model outcomes: queue A stopped before CUDA because its nested output parent was missing; queue B completed its first valid run but its parent compared a raw-file config hash against a semantic config hash. That completed run is retained. Remaining runs use the unchanged, reviewed single-run launcher and original frozen contracts serially. No scientific run is automatically retried, and no numerical implementation or hyperparameter changes were made for these operational fixes.
