# Banking v10 official-test memory launcher

`tools/launch_banking_test_memory_policy_v10.py` is a dedicated wrapper for the sealed Banking v10 evaluator. It exists because the general memory launcher binds `--training-root` to the train/dev pack parent, while the official-test evaluator needs `--training-root` to point at the sealed nine-run output root.

The launcher consumes a `banking-v10-test-memory-launch-v1` JSON contract whose exact required fields are declared in `CONTRACT_KEYS` in the launcher. The contract binds the launcher and evaluator bytes, contract-builder bytes, full 24-file source map and source lock, raw and logical config hashes, model assets through the frozen config, training pack bytes, train/dev manifest bytes, main training root and seal, main release, foundations, evaluation contract, and the intended test CSV path and source pin. Create this contract only after the complete nine-run seal and its foundation references are available; the launcher does not infer a best checkpoint or build the contract itself.

Keep the train/dev pack separate from the main training root. `training_pack` is the verified train/dev artifact passed to `_source_prepare`; `training_root` is the directory containing the sealed seed/arm run directories used by `verify_run_artifacts`. The launcher forwards `training_root` unchanged to the evaluator. It rejects a value equal to the pack's parent.

The test CSV must be the sibling `raw/test.csv` of the verified original publisher cache's `raw/train.csv`. The train CSV is pinned to 839,073 bytes and SHA-256 `b06e26ac675513959a63135f11b94ea7786ed02da65db93a5650d8838cbc664b`. The test CSV pin is revision `9d081458ff52e53cf7e848f414e6e9344e4e6696`, 239,961 bytes, SHA-256 `d12d6e3bc4c3103966ae786dc435913c0c563dfa328f5a3646d0e62cfeeb474d`. Preflight checks the sibling path and the contract's metadata pin without opening test bytes. The evaluator verifies the test bytes after all sealed-grid checks.

At launch, the wrapper verifies contract/source/config/data/model bindings, then calls the frozen evaluator in `preflight` mode with a separate fresh preflight output directory and without `--test-csv`. It requires a passing CPU checkpoint audit of all nine terminal contexts, with test payload unread, model unloaded, CUDA uninitialized, and zero optimizer updates. It rechecks the bound source and model assets, sets the process-local allocator policy `garbage_collection_threshold:0.7`, and queues the 0.8 CUDA memory-fraction callback. Only then does it invoke evaluator `evaluate` mode. The evaluation remains read-only, with the frozen global 77-class scoring policy, a 600,000-backbone-forward ceiling, and a 21,600-second wall ceiling.

The launch record is a separate file outside the source, model, pack, publisher-cache, foundation, and run trees. It records CPU preflight status, callback registration/application state, terminal result hash, and failures; there are no automatic retries. A failed evaluation preserves the callback state reached before failure.
